# Project Journal

**Role:** Gateway Backend and Distributed Rate Limiting  
**Tech Stack:** Java 17, Spring Boot, Redis, Bucket4j, PostgreSQL, Docker

## Week 1: Basic Gateway

- Built a **reverse proxy** that forwards `/test/**` requests to `httpbin`.
- Implemented an **in-memory request counter** that returns HTTP `429 Too Many Requests` with a `Retry-After` header after 5 requests.
- **Issue:** Routes returned 404 due to an incorrect property prefix for the MVC gateway. Fixed it by correcting the configuration.
- **Limitations:** The counter was global, did not refill, and could not maintain consistent limits across multiple instances.

## Week 2: Redis Rate Limiting

- Integrated **Redis using Docker** and implemented a **Bucket4j token bucket** with 5 tokens and a refill interval of 20 seconds, keyed by client IP.
- Verified that a burst of 8 requests admitted 5 requests and that the bucket refilled after approximately 20 seconds.
- **Issues resolved:**
  - Incorrect Maven dependencies.
  - Outdated Bucket4j builder API.
  - Stale Redis port configuration.
  - Existing bucket state in Redis masking configuration changes, resolved by clearing Redis during testing.

## Week 3: Proving Correctness

- **Concurrency Testing:** Used Testcontainers to test 200 concurrent requests across 20 threads, verifying that exactly 20 requests were admitted under the configured limit.
- **Fail-Open Behaviour:** Implemented fail-open handling so that requests are allowed when Redis is unavailable, with a warning logged. Rate-limit enforcement resumes automatically when Redis recovers.
- **Configurable Rate Limiting:** Introduced the `ApiLimitProvider` interface to remove hardcoded limits and added a second algorithm: **sliding window**.
- **Multi-Instance Validation:** Tested two gateway instances on ports `8080` and `8081` sharing a single Redis budget. Verified that 6 requests were admitted in total rather than 10.
- **Latency Validation:** Measured approximately **26.5 ms of added latency**, within the 50 ms target.
- **Issue:** Resolved a Testcontainers Docker API version mismatch using `docker-java.properties` with `api.version=1.44`.

## Week 4: Persistence and API Management

- Integrated **PostgreSQL** to store registered APIs and their rate-limiting policies.
- Extended `ApiLimitProvider` to retrieve rate limits from the database instead of relying on an in-memory placeholder.
- Integrated my teammate's **authentication implementation** with the backend.

## Week 5: Integration and Frontend

- Connected the **API gateway, PostgreSQL database, authentication, and frontend** into a single application.
- Contributed to **UI design** and frontend-to-backend connectivity.
- Focused primarily on backend development and integration, with limited frontend involvement.

## 12 October 2026: Production Fixes

- **Real Client IP Handling:** Resolved inconsistent rate-limit buckets behind Cloudflare, where requests were being identified by edge-server IPs instead of the actual client IP. Added configurable support for `CF-Connecting-IP`, disabled by default to avoid trusting spoofable headers unless explicitly enabled in a trusted deployment.
- **Readable URLs:** Enabled client-facing routes such as `/g/weatherhello/...` instead of `/g/4/...`, making API access more readable.
- **Uptime Monitoring:** Configured UptimeRobot to monitor the deployed application and ping the site to track downtime and help reduce Render free-tier spin-downs.
